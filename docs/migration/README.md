# Path of Building → C# / .NET + Avalonia

Migration plan and ticket index. Target directory: `dotnet/` in this repository, alongside the Lua tree so the reference implementation stays available as a conformance oracle.

## Scope — the real numbers

The repository is 5.1M lines of Lua. **It is not a 5.1M-line rewrite.**

| Tree | LOC | Nature |
|---|---:|---|
| `src/TreeData/` | 4,112,746 | JSON mechanically dumped to Lua table syntax. Transcode, don't rewrite. |
| `src/Data/` | 816,748 | **93.8% carries `-- This file is automatically generated, do not edit!`** (105 of 139 files). Codegen target. |
| `src/Export/` | 51,838 | Dev-only GGG `.dat` extractor. Excluded from shipping via `manifest.cfg:14`. **Not ported.** |
| `src/Classes/` | 46,850 | ~27% pure domain, ~42% tabs, ~10% reusable widgets, rest domain-bound UI. |
| `src/Modules/` | 43,279 | Calc engine + app shell. |
| `src/*.lua` | 1,942 | Launch, headless wrapper, host API stub. |

**Actual port surface: ~92k LOC of hand-written code**, plus ~120–140 small behaviour methods extracted from data files, plus a mechanical data transcoding step.

## Key architectural decisions

**1. The three existing seams are gifts — use them.**
`src/_SimpleGraphic.def.lua` (516 lines) is a complete `---@meta` declaration of the entire host API. An exhaustive scan of every capitalised bare call across all 445 Lua files confirms it is complete and exhaustive — the interface definition is already written. `src/HeadlessWrapper.lua` proves the calc engine already runs with no graphics host. `src/Modules/CalcBase.lua` carries LuaLS `---@class Output` annotations — a free skeleton for the C# `Output` type.

**2. Numerics before anything else.**
Engine results depend on exact rounding: `round(modResult, 2)` per name in `More` (`src/Classes/ModDB.lua:197`), `m_floor(base/div + 0.0001)` in Multiplier tags (`src/Classes/ModStore.lua:403`), `m_modf(round(v*scale,2))` in `ScaleAddMod` (`ModStore.lua:82`), plus `data.highPrecisionMods` overrides, which use **raw `math.floor` with no epsilon** (`ModDB.lua:194-195`). Common.lua defines eight such helpers and they are not interchangeable. .NET's `Math.Round` is banker's rounding by default; Lua's `round` is half-up toward positive infinity. `LuaCompat` is ticket 02 for a reason.

**3. Conformance oracles before porting, not after.**
`src/Data/ModCache.lua` is 23,215 pre-parsed mod lines — a complete answer key for the parser port that already exists in the repo. `spec/` has 44 busted spec files and 5 golden builds with ~474 output keys each. These become the migration's progress metric: "we parse 21,840 / 23,215 lines correctly" is a number you can report daily.

**4. Global mutable state gets threaded from the first commit.**
`GlobalCache` (`src/Data/Global.lua:356`), `modLib.parseModCache`, and `globalOutput`/`globalBreakdown` file-locals in `CalcOffence.lua:65-67` are implicitly single-threaded hidden parameters. Retrofitting a `CalcSession` after `calcFullDPS` is written is a second rewrite.

**5. Maximum library reuse.**
Avalonia 11 + SkiaSharp for rendering; `System.IO.Compression.ZLibStream` for build codes; `HttpClient` + Polly replacing libcurl and the entire `LaunchSubScript` threading mechanism; `System.Xml.Linq` for build files; MessagePack-C# for shipped data; Velopack replacing the hand-rolled `Update.exe`/`lzip`/`manifest.xml` updater. Custom code is reserved for what genuinely has no library: the layer-sorted draw queue, the bitmap font atlas reader, the passive tree canvas, and the mod engine itself.

## What gets deleted rather than ported

- `LaunchSubScript` / `OnSubCall` / `OnSubError` / `OnSubFinished`. All seven uses are HTTP or a socket listener. The `subList` mechanism materialises names as real globals inside a child Lua state and marshals calls back to the parent — `IProgress<T>` plus `await` replaces it exactly, and the "is this global present?" ambiguity (`UpdateCheck.lua:222`) disappears at compile time. Also removes a string-concatenated-Lua-source pattern that is an injection hazard.
- The `ConExecute` cvar console — two commands used, both window setup (`Launch.lua:12-13`).
- `Update.exe` + `UpdateApply.lua` + `LaunchInstall.lua` + the `lzip` dependency → Velopack.
- Unused host surface: `ArtHandle`, `TexHandle`, `Texture`, `SetBlendMode`, `SetClearColor`, `SetCursorPos`, `ShowCursor`, `AbortSubScript`, `IsSubScriptRunning`, `SetCallback`/`GetCallback`.
- `ScrollBarControl` (327 → 0, `ScrollViewer`), most of `EditControl` (~700 of 761 lines → `TextBox`), the ~20 `ListControl` subclasses (~4,000 LOC → DataTemplates).

## The five highest-risk items

1. **`src/Classes/PassiveTreeView.lua` (1,856) + `PassiveTree.lua` (1,062)** — textured-quad connectors with atlas UVs, sprite sheets with per-zoom mipmap variants, 8 interleaved draw sub-layers, O(n) per-frame node hit-testing over ~1300+ nodes. No library does this. Its own project. (Ticket 40)
2. **The function-valued property system.** `Control:GetProperty` (`src/Classes/Control.lua:73-79`) calls any property that is a function, every frame. `src/Modules/Build.lua:148-153` computes a width from six siblings. Hundreds of these, each needing individual dependency analysis to become a binding. Highest-volume, most tedious, no automated path. (Ticket 33)
3. **Font metrics.** Layout is computed by calling `DrawStringWidth()` at runtime throughout (`Main.lua:1680`, `Tooltip.lua:387`). The originals are pre-rasterised bitmap atlases (`runtime/SimpleGraphic/Fonts/*.tga` + `.tgf`), which is why widths are stable integers. Vector fonts will shift every hand-tuned pixel constant in 47k lines of UI code. (Ticket 28)
4. **Synchronous full-engine recalc on the draw thread.** `build.buildFlag` → `wipeGlobalCache()` → `BuildOutput()` inline (`src/Modules/Build.lua:1258-1272`). Acceptable in an immediate-mode loop; freezes an Avalonia window. (Ticket 34)
5. **`src/Modules/ModParser.lua` (7,021 LOC)** — natural-language mod parsing, required because 20,792 LOC of `src/Data/Uniques/` and every `<Item>` in every build file are stored as free text. (Tickets 12–14)

## Lua-side toolchain (for every oracle and transcoder ticket)

The conformance oracles run the real Lua engine headlessly. Constraints, all measured:

**LuaJIT is required. Stock Lua 5.1 cannot run PoB at all** — three independent blockers:
- `goto`/labels (Lua 5.2 syntax) in 20 places outside TreeData; `src/Modules/Data.lua:228` is hit first.
- `src/Launch.lua:18` calls `jit.opt.start('maxtrace=4000','maxmcode=8192')`.
- `bit.*` is a LuaJIT builtin; `src/Modules/ModTools.lua:15` binds `bit.band`.

So "verify under both interpreters" is not a meaningful check for anything that loads the engine. It *is* meaningful for standalone scripts (e.g. the `LuaCompat` dump, which sources only `Common.lua` definitions).

**Invocation** — from `src/`:
```
LUA_PATH="../runtime/lua/?.lua;../runtime/lua/?/init.lua;./?.lua;;" \
LUA_CPATH="/usr/local/lib/lua/5.1/?.so;;" \
luajit -e 'dofile("HeadlessWrapper.lua")'
```
Requires the `luautf8` rock (`luarocks --lua-version=5.1 install luautf8`). On Ubuntu the SDK and interpreter come from the distro repos (`apt-get install dotnet-sdk-10.0 luajit luarocks`); `builds.dotnet.microsoft.com` is not reachable from this environment, so the official `dotnet-install.sh` does not work.

**One upstream fix was required**: `src/Modules/Main.lua:342` used `count += 1`, valid only under the patched LuaJIT PoB ships as `runtime/lua51.dll`. Lua reports that at parse time regardless of reachability, so `HeadlessWrapper.lua` would not load. Changed to `count = count + 1`, identical under both.

## ⚠️ The headless engine swallows errors — read this before writing any generator

`launch:OnFrame` (`src/Launch.lua:112`) runs the entire calculation inside `PCall` and **does not rethrow**. On error it stores the message in `launch.promptMsg` and continues; `Launch.lua:115` then sends a build that crashed on its first calculation back to the build list via a deferred `main:SetMode`.

**A generator that wraps only its own calls in `pcall` will see a clean run, read `build.calcsTab.mainOutput`, and record the *previous* build's output as this build's answer.** No error, no exception, plausible numbers, silently poisoned oracle. For a golden corpus that is the worst available failure mode — every engine ticket downstream would then be verified against corrupt data.

Any tool that drives the engine must:
1. Read `launch.promptMsg` after every `runCallback` and treat non-nil as a failed build.
2. Check for the pending deferred mode switch, which marks a build that was ejected.
3. Clear the prompt before the next build so failures cannot leak forward.
4. Record failures explicitly rather than dropping them.
5. **Prove the detector fires** — inject a synthetic `ShowErrMsg` and confirm the error is reported, outputs withheld, prompt cleared, and the next build recovers. A failure detector never shown to fire is not a detector.

`dotnet/tools/fuzz/apply.lua` implements this and is the reference.

## Known upstream quirks the port must decide about

- **`Multiplier:QualityOnFlask nil`** — a mod name with a literal `" nil"` appended, from a Lua string concat against a nil value. Present in 3 of the 5 test builds' `modDB`. It is pinned in the #7 golden dumps. Decide deliberately whether the C# port reproduces it or fixes it; either way it must be a conscious choice, because it changes what queries match.
- **Tag arrays can contain holes.** `createMod` builds them with `select(tagStart, ...)` inside a table constructor, so a nil mid-list leaves a hole. `formatTags` and `ModStore:EvalMod` both walk with `ipairs` and stop there, so the shadowed tags are dead in the engine. A C# `List<ModTag>` has no holes, so a faithful port drops them — which is correct, not a bug. Two mods in the ModCache corpus hit this.
- **Insertion order within a mod bucket is not reproducible run to run.** The #7 dumps sort by canonical encoding and discard array order. If the port ever depends on within-bucket order, that dependency cannot be tested against Lua.
- **The engine stores negative zero** (an inactive Chill contributes `-0 INC ActionSpeed`). Lua prints `-0`; `%d` formatting and `JsonElement.GetDouble()` both silently fold the sign. Pinned by tests in #7.
