# 03 — Lua → JSON → MessagePack data transcoder

**Phase** 0 · **Depends on** 01, 04 (behaviour-key contract) · **Blocks** 05, 15–19

## Goal
Mechanically convert the 93.8% of `src/Data/` and effectively all of `src/TreeData/` that is generated, without hand-writing any of it.

## Scope
`dotnet/tools/transcode/` — a Lua script run under stock Lua/LuaJIT (not the SimpleGraphic host).

**Two-tier representation:**
- **Tier 1 (repo, source of truth): JSON.** Diffable, reviewable in PRs. The community hand-edits this data — all 25 `src/Data/Uniques/` files are hand-maintained.
- **Tier 2 (shipped artifact): MessagePack**, built in CI from Tier 1. Integer keys, AOT source-generated resolver (`mpc`), `Lz4BlockArray` compression.

**Input inventory:**
| Group | Files | LOC | Notes |
|---|---:|---:|---|
| `Data/StatDescriptions/` | 20 | 382,376 | pure declarative, integer-keyed |
| `Data/` root | 90 | 282,144 | mostly pure tables |
| `Data/Skills/` | 10 | 93,532 | **main closure concentration** — see ticket 04 |
| `Data/TimelessJewelData/` | 3 + 41 bin | 25,584 | keep binary format as-is |
| `Data/Uniques/` | 25 | 20,792 | Lua long-strings of raw item text — pass through verbatim |
| `Data/Bases/` | 22 | 12,320 | pure declarative, zero logic |
| `TreeData/` | 61 | 4,112,746 | already mechanically-dumped JSON, lossless round-trip |

**Segment the pack by group and mirror laziness, not eagerness.** Current Lua loads ~608k LOC eagerly and only ~208k lazily. Target:
- Eager: `Bases`, `Gems`, `Skills`, `Minions`, mod tables.
- Lazy: `StatDescriptions` (382k — tooltips only), `TradeSiteStats` (92k), `QueryMods` (67k), `FlavourText`, `Rares`, `Spectres`.
- TreeData: load **one version on demand**, never all 41.

## Gotchas
- **Do not generate C# source.** The Lua codebase already hit this wall — see the comment at `src/Modules/Main.lua:310`: `ModCache.lua` is split into 5 IIFEs of 5,000 statements each to dodge LuaJIT's per-prototype constant limit. In C# it is worse: the data is non-blittable object graphs, so Roslyn cannot use fast RVA blobs, the 64KB method IL limit forces the same artificial chunking into hundreds of `InitPart_N()` methods, and a league data update becomes a full rebuild.
- `src/Data/ModCache.lua` is a derived memoisation cache regenerated by `main:SaveModCache()` (`Main.lua:315`), **not source data**. Do not transcode it as data — it is the parser oracle (ticket 05).
- Every `Bases/*.lua` and `Skills/*.lua` opens with a parameter-injection wrapper (`return function(itemBases)`, `Bases/amulet.lua:3`). That is a DI idiom, not behaviour — all 22 `Bases/` files contain zero executable code.
- `Data/Uniques/Special/Generated.lua` is pure string manipulation synthesising legacy variants. **Run it once at transcode time and emit the expanded results as data.** Zero runtime code needed.
- The `mod(...)` / `skill(...)` / `flag(...)` DSL calls (2,203 / 1,050 / 263 occurrences) inside data literals are calls, not closures — they evaluate to plain records at load time and serialise fine once the constructors exist.

## Acceptance
- Round-trip check: transcoded JSON reloaded into Lua produces a table deep-equal to the original for all 105 generated files.
- CI step producing the MessagePack artifacts.
- Measured cold-start deserialisation for the eager set. Target: low hundreds of ms.

## Libraries
`dkjson` (already in `runtime/lua/`) for the Lua side. MessagePack-C# with AOT resolver, `System.Text.Json` source-gen for Tier 1 on the C# side.
